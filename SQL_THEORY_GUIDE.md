# 🗺️ Полная карта SQL: От сырых данных до Senior-окон

> **Главный закон SQL:** Вся путаница в голове исчезает, когда ты понимаешь, что SQL — это **конвейер фабрики с 6 последовательными цехами**.  
> Каждый инструмент работает **строго в своём цехе** и в своё время.

```
Таблицы на диске
       │
       ▼
[ Цех 1: FROM + JOIN ]        ──► Соединяем нужные таблицы вместе
       │
       ▼
[ Цех 2: WHERE ]              ──► Выбрасываем лишние сырые строки
       │
       ▼
[ Цех 3: GROUP BY ]           ──► Раскладываем строки по «кучкам»
       │
       ▼
[ Цех 4: HAVING ]             ──► Выбрасываем целые кучки после подсчёта
       │
       ▼
[ Цех 5: SELECT + Окна ]      ──► Считаем итоги, клеим ярлыки и считаем окна
       │
       ▼
[ Цех 6: ORDER BY + LIMIT ]   ──► Расставляем результат на полке витрины
```

---

## 🏭 ЦЕХ 1: Откуда берём данные (`FROM` и `JOIN`)

### 1. `FROM таблица`
Просто указывает, какую таблицу снять с полки.
```sql
FROM transactions
```

### 2. `JOIN` (Склейка таблиц провод к проводу)
Нужен, когда данные лежат в разных таблицах (например, имена клиентов в `users`, а их траты в `transactions`).
* **`JOIN` (или `INNER JOIN`):** оставляет только тех, кто есть **в обеих** таблицах (клиент совершил хотя бы 1 покупку).
* **`LEFT JOIN`:** сохраняет **всех** клиентов из левой таблицы, даже если у них 0 покупок (у них в графе трат будет `NULL` — спящие клиенты).

**Формула:**
```sql
FROM users u
JOIN transactions t ON u.user_id = t.user_id
```
*(Буквы `u` и `t` — это просто короткие клички таблиц, чтобы не писать длинные названия).*

## 🏭 ЦЕХ 2: Входной фейсконтроль (`WHERE`)

* **Когда работает:** ДО любых группировок, окон и расчётов.
* **Что делает:** отбирает сырые строки.
* **Чего он НЕ умеет:** он **не видит** средние чеки, суммы групп и оконные функции, потому что их на этом этапе ещё физически не посчитали!

**Пример:**
```sql
WHERE status = 'success' AND age >= 18
```

---

## 🏭 ЦЕХ 3: Сортировочная станция (`GROUP BY`)

* **Физика процесса:** Мясорубка.
* Если у нас было 2 000 чеков по 5 городам, то `GROUP BY city` **схлопнет** 2 000 строк в **5 строк** (по одной строке на каждый город).
* Все отдельные чеки уничтожаются — на экране остаются только общие итоги по кучкам.

```sql
GROUP BY city
```

---

## 🏭 ЦЕХ 4: Фильтр готовых кучек (`HAVING`)

* **Главная разница с `WHERE`:**
  * `WHERE` выбрасывает **отдельные чеки** ДО группировки.
  * `HAVING` выбрасывает **целые группы** ПОСЛЕ того, как посчитаны суммы и средние.

**Пример:**
```sql
-- Оставляем только те города, где суммарная выручка превысила миллион:
HAVING SUM(amount) > 1000000
```

## 🏭 ЦЕХ 5: Калькулятор, Разметчик и Окна (`SELECT`)

Именно здесь происходят все вычисления. Разделим их на 4 семьи инструментов:

### 1. Агрегаторы (Считают итоги кучек из `GROUP BY`):
* `COUNT(*)` или `COUNT(tx_id)` — считает штуки строк.
* `COUNT(DISTINCT user_id)` — считает только **уникальных** людей (без дублей).
* `SUM(amount)` — складывает все рубли.
* `AVG(amount)` — находит средний чек.
* `ROUND(число, 2)` — округляет до 2 знаков (до копеек).

### 2. Наклейщик ярлыков (`CASE WHEN`):
* **Физика:** Он **НЕ выбрасывает строки**! Он просто смотрит на строку и приклеивает новую бирку-категорию в соседний столбец.
```sql
CASE 
    WHEN age <= 25 THEN 'Молодые'
    WHEN age <= 45 THEN 'Взрослые'
    ELSE 'Зрелые'
END AS возрастная_категория
```

### 3. Даты во времени (`strftime`):
* Даты хранятся с секундами (`2026-05-14 12:40:22`).
* Чтобы сгруппировать по месяцам, мы отрезаем дни и часы:
```sql
strftime('%Y-%m', tx_date) AS месяц
```

### 4. Оконные функции (Суперсила аналитика — `OVER`):
* **Главный закон:** Окно **НЕ схлопывает строки**! Если было 2 000 чеков, на экране останется 2 000 чеков, но рядом появится вычисленный столбец.

**Анатомия окна:**
```text
ФУНКЦИЯ() OVER (PARTITION BY комната ORDER BY порядок)
```

| Функция | Что делает внутри окна |
| :--- | :--- |
| **`ROW_NUMBER()`** | Счётчик строк (`1, 2, 3...`). В скобках пусто, потому что он просто считает строки подряд. |
| **`DENSE_RANK()`** | Призовые места без дырок при одинаковых суммах (`1, 1, 2, 3`). Нужно для «Топ-3 покупок каждого клиента». |
| **`SUM(amount)`** | **Копилка (Running Total):** нарастающий итог от старых покупок к новым. |
| **`LAG(tx_date)`** | **Подглядывание назад:** достаёт дату из предыдущей строки, чтобы посчитать дни между покупками. |

* `PARTITION BY user_id` — **межкомнатная стена**: у каждого клиента свой личный расчёт (счётчик сбрасывается в 1).
* `ORDER BY tx_date ASC` — стрела времени: обход от старых к новым.

## 📦 НАДСТРОЙКА: Виртуальные коробки (CTE: `WITH ... AS`)

* **Зачем нужен:** Оконные функции вычисляются на шаге 5 (`SELECT`). Поэтому на шаге 2 (`WHERE`) база ещё не знает, что такое `ранг` или `номер_покупки`.
* **Решение:** Мы упаковываем наш первый запрос в коробку (CTE) и во втором запросе спокойно фильтруем готовые данные!

```sql
WITH витрина_с_окнами AS (
    SELECT 
        user_id,
        amount,
        DENSE_RANK() OVER (PARTITION BY user_id ORDER BY amount DESC) AS ранг
    FROM transactions
    WHERE status = 'success'
)
SELECT *
FROM витрина_с_окнами
WHERE ранг <= 3;
```

## 🏭 ЦЕХ 6: Финальная витрина (`ORDER BY` и `LIMIT`)

* **`ORDER BY колонка ASC`** — от меньшего к большему (в гору / от старых к новым). По умолчанию.
* **`ORDER BY колонка DESC`** — от большего к меньшему (с горы Down / от богатых к бедным).
* **`LIMIT N`** — оставить только первые N строк.
